Trust boundary

Two delivery lanes. One stable contract.

Official release
Standard firmware and mandatory LittleFS image, signed through the existing production release workflow.
OLED Pull OTA
Custom build
Exact feature and plugin combination with full provenance, isolated from production signing.
USB install

A custom build may include Pull OTA, but that client remains on the official signed release channel.

Delivery plan

Four phases, each useful on its own.

Phase 1

Package and catalog

One validated source of truth for assets, patches, refs, dependencies, and conflicts.

Result: approved package contract
Phase 2

Secure patch build

Exact patch application in a temporary checkout with deterministic provenance.

Result: safe custom binaries
Phase 3

Artifact cache

Canonical combination hashes and durable public downloads.

Result: build once, reuse
Phase 4

Public service

Rate-limited requests, status tracking, and a single self-service interface.

Result: build on demand

The outcome

A smaller core. A safer extension path. Firmware that fits the user.

For maintainers

Plugin compatibility is isolated from the stable firmware path.

For contributors

A reviewed package can target main or a specific release without permanent core changes.

For users

Choose only what is needed, then download a reproducible build.
